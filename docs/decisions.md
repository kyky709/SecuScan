# Décisions

Une ligne datée par décision structurante : décision, raison, options écartées.
Les décisions de notation détaillées sont expliquées dans [22-notation.md](22-notation.md).

| Date | Décision | Raison | Options écartées |
|---|---|---|---|
| 2026-11-15 | Une seule application **Next.js 16.4 (App Router)** en TypeScript strict, Tailwind CSS 4, lint/formatage **Biome**, tests **Vitest**, Node.js **24** | Même socle que les autres projets (TypeScript strict, Biome, Vitest, Node 24) ; interface et API dans un seul projet déployable sur Vercel | Front React + API séparée (Fastify) : deux déploiements ; ESLint + Prettier : Biome fait les deux, plus vite |
| 2026-11-15 | L'analyse s'exécute **côté serveur** (route `POST /api/scan`) | Un navigateur ne peut ni lire les en-têtes d'un autre site (CORS) ni inspecter la négociation TLS | Analyse dans le navigateur (impossible) ; Server Action (moins réutilisable qu'une API testable avec curl) |
| 2026-11-15 | Architecture « **cœur fonctionnel, coquille impérative** » : sondes réseau → `ScanContext` → contrôles purs → notation | Les contrôles deviennent des fonctions pures, testables sans réseau ; les entrées/sorties sont concentrées dans `network/` | Chaque contrôle fait ses propres requêtes (lent, redondant, difficile à tester) |
| 2026-11-15 | Client HTTP écrit sur **`node:http` / `node:https`** avec une fonction `lookup` qui valide chaque adresse | Seul moyen simple de vérifier l'adresse **au moment de la connexion** (anti DNS rebinding), de suivre les redirections une à une et de lire les informations TLS | `fetch` global (pas de contrôle du DNS) ; bibliothèque `request-filtering-agent` (moins pédagogique) |
| 2026-11-15 | Politique **anti-SSRF par liste de blocage** : seules les adresses publiques « unicast » sont autorisées (IPv6 dans `2000::/3`), toutes les adresses d'un nom sont vérifiées, NAT64/6to4/Teredo refusés, ports 80 et 443 uniquement, `agent: false` | Cas 2 de l'OWASP SSRF Prevention Cheat Sheet (« l'application peut contacter n'importe quelle adresse externe ») ; les pièges ont été vérifiés par expérience sur Node 24 (connexions keep-alive qui contournent `lookup`, IP littérales non résolues…) | Liste d'autorisation (impossible pour un scanner) ; décodage des adresses NAT64 (plus fragile) |
| 2026-11-15 | Notation inspirée de **MDN HTTP Observatory (algorithme v6)** : base 100, bonus « tout ou rien » si le score après pénalités atteint 90, plancher 0, pas de plafond ; **7 lettres A+ à F** (seuils 100/85/70/55/40/25) | Méthode publique, éprouvée et vérifiée dans le code source d'Observatory ; le cahier des charges demande une note « de A à F » | Barème de securityheaders.com (points par en-tête présent, sans analyse fine) ; notes avec + et − d'Observatory (13 niveaux, moins lisible) |
| 2026-11-15 | Écarts assumés avec Observatory : contrôles **TLS** ajoutés ; COOP/COEP/CORP regroupés (+5) ; scripts en `http://` traités par « contenu mixte » et non par SRI ; `ALLOW-FROM` traité comme absent ; en-têtes dupliqués interprétés **comme les navigateurs** (spécifications) ; préchargement HSTS estimé d'après l'en-tête ; pas de double pénalité HSTS/certificat | Chaque problème est compté une seule fois, à l'endroit le plus parlant, et les verdicts reflètent le comportement réel des navigateurs | Copier Observatory à l'identique (y compris ses particularités historiques) |
| 2026-11-15 | Références : **OWASP Top 10:2025**, **ASVS 5.0.0**, Cheat Sheet Series, **WSTG v4.2** (version « latest » pour les tests absents de la v4.2), Secure Headers Project, MDN, RFC — URL vérifiées le 2026-11-15 et centralisées dans `src/lib/scanner/references.ts` | Demande explicite de références OWASP ; un seul fichier à mettre à jour lors des nouvelles éditions | Liens recopiés dans chaque contrôle |
| 2026-11-15 | `cacheComponents` (Partial Prerendering) **désactivé**, CSP stricte à **nonce** posée par `src/proxy.ts`, rendu dynamique forcé (`connection()`) | Le guide CSP de Next.js 16 indique que le PPR est incompatible avec une CSP à nonce ; un outil de sécurité doit appliquer ce qu'il recommande | CSP avec `'unsafe-inline'` (pénalisée par SecuScan lui-même) ; SRI expérimental de Next.js |
| 2026-11-15 | **Aucune donnée conservée** : pas de compte, pas de cookie, pas d'historique ; l'IP du client n'est utilisée que hachée (SHA-256) pour la limitation de débit | Minimisation des données (RGPD) ; rien à protéger, rien à fuiter | Historique des analyses en base de données |
| 2026-11-15 | Limitation de débit **par client et par site analysé** : en mémoire par défaut, **Upstash Redis** si les variables d'environnement existent | Sur Vercel, plusieurs instances coexistent : un compteur en mémoire n'est qu'approximatif ; Redis le rend global sans rendre le service obligatoire | Pas de limitation (abus) ; Redis obligatoire (complexifie l'installation) |
| 2026-11-15 | Vercel : Node.js **24.x** épinglé (`engines`), région **cdg1 (Paris)** | Vercel déploie Node 26 par défaut ; Paris rapproche le scanner des utilisateurs et des sites français | Valeurs par défaut (Node 26, Washington `iad1`) |
| 2026-11-15 | GitHub Actions **épinglées par SHA**, Dependabot (npm + actions), **CodeQL** | Bonnes pratiques de chaîne d'approvisionnement (OWASP Top 10:2025 A03) pour un projet de sécurité | Étiquettes de version modifiables (`@v7`) |
| 2026-11-15 | Langues : identifiants de code en anglais ; commentaires, messages, interface et documentation en français | Convention des autres projets ; documentation accessible en français | Tout en anglais |
| 2026-11-15 | Licence **MIT** | Projet open source, librement réutilisable | Pas de licence (tous droits réservés) |
| 2026-11-16 | Grille alignée sur **MDN Observatory v6** pour trois cas : `X-Frame-Options` DENY/SAMEORIGIN **+5**, Referrer-Policy permissive (`no-referrer-when-downgrade`…) **−5**, COOP isolant **+5** | Scores comparables avec Observatory (vérifié : identiques sur github.com, mozilla.org, owasp.org) | Grille initiale du cahier des charges (0 point pour ces trois cas) |
| 2026-11-16 | CSP : plusieurs politiques appliquées en même temps → chacune est notée et **la plus stricte l'emporte** ; directive répétée dans une politique → **CSP invalide (−25)** ; `'strict-dynamic'` sans nonce ni empreinte suit la spécification (tous les scripts bloqués, signalé en détail) | Le navigateur applique toutes les politiques ; une directive répétée n'a aucun effet et trahit une erreur | Intersection exacte des politiques (complexe à expliquer) ; −25 pour `'strict-dynamic'` sans nonce (Observatory) |
| 2026-11-16 | `frame-ancestors` qui autorise tout (`*`, schéma seul) = **aucune protection (−20)**, même avec `X-Frame-Options: DENY` | Les navigateurs ignorent `X-Frame-Options` dès que `frame-ancestors` est présente | +5 pour toute `frame-ancestors` (Observatory) |
| 2026-11-16 | Certificat : « pas de HTTPS » (−30) seulement si la sonde HTTPS a **aussi** échoué | Ne pas pénaliser ce qu'on n'a pas pu observer quand HTTPS fonctionne | −30 dès que la sonde TLS échoue |
| 2026-11-16 | Vérification d'origine de l'API par comparaison des **hôtes** (`X-Forwarded-Host`, puis `Host`) | Hors de Vercel, Next.js écrit son propre nom de serveur dans `request.url` : la comparaison bloquerait les requêtes légitimes | Comparaison avec `request.url` |
| 2026-11-16 | Adresses NAT64, 6to4 et Teredo **refusées** | Elles peuvent encapsuler une IPv4 interne | Décoder l'IPv4 encapsulée (plus fragile) ; conséquence assumée : pas d'analyse depuis un réseau IPv6 seul avec NAT64 |
| 2026-11-19 | Tests écrits **à partir des spécifications** et complétés par des **invariants transversaux** (robustesse des 18 contrôles sur ~400 contextes, modificateur toujours présent dans la grille) | Des tests calqués sur le code reproduisent ses erreurs ; les invariants ont trouvé des bogues invisibles aux tests unitaires | Tests calqués sur l'implémentation |
| 2026-11-20 | Analyseurs **linéaires** : boucles ou expressions sans retour arrière ambigu ; test de performance de non-régression (entrées de 60 000 caractères) | Faille ReDoS : 13 s de calcul synchrone pour une page piégée, que le délai global ne peut pas interrompre | Limiter la taille des valeurs analysées (changerait les verdicts) ; entrées de 2 Mio dans le test (une régression bloquerait la CI au lieu d'échouer) |
| 2026-11-20 | Messages de blocage **sans l'adresse résolue** pour un nom d'hôte (seulement sa catégorie) | Un site piégé pouvait faire lire, rapport après rapport, les adresses du DNS interne de l'hébergeur | Afficher l'adresse (utile au débogage, mais fuite d'information) |
| 2026-11-20 | Toute valeur venue du site est **raccourcie** dans les phrases (`shorten`, 120 caractères) et toute table indexée par une telle valeur est lue avec **`lookup`** (`Object.hasOwn`) | Des en-têtes de 60 Ko rendaient les constats illisibles ; `constructor` faisait afficher du code JavaScript | Tronquer les phrases entières (illisible) |
| 2026-11-20 | Résilience réseau : **une seule** nouvelle tentative après `CONNECTION_RESET` (500 ms) ; TLS 1.0/1.1 testés **après** la négociation principale ; certificat jugé d'après la **connexion HTTPS** si la sonde TLS échoue | Des serveurs coupent les connexions simultanées d'un client (badssl.com) : verdicts « non vérifié » ou analyses impossibles | Réessayer tous les échecs (analyses plus longues, plus de requêtes) ; tout lancer en parallèle |
| 2026-11-20 | Les cookies **anti-CSRF** (`csrf`, `xsrf`) ne sont jamais classés « cookie de session » | Dans le schéma « double soumission », JavaScript doit les lire : exiger `HttpOnly` pousserait à casser la protection CSRF | Classement par mots-clés seul (`XSRF-TOKEN` contient « token ») |
| 2026-11-20 | Les grilles de notation sont documentées dans **`docs/22-notation.md`**, référence unique citée par les commentaires du code | Le dépôt doit contenir tout ce que le code cite ; une seule référence lisible par tous | Garder un document hors dépôt |
| 2026-11-23 | Historique Git en **commits thématiques** au format **Conventional Commits** (`feat`, `test`, `docs`, `chore`…) | Historique lisible par couche (outillage, moteur, contrôles, API, interface, documentation) | Un seul commit initial ; messages libres |
